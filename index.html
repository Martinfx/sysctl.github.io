03 — Upstream

      
Plugged into the whole FreeBSD world

      

        None of this is a private fork that goes nowhere. Board support starts on a branch,
        hardens in a SoCBSD arena, goes through review, and ends up in the trees and wiki pages
        the rest of the project actually uses.
      

    


    
    
      
  1. 
        01
        
    Branch
    
        
    A per-board branch in Martinfx/freebsd-src, built and booted on real hardware.
    
      
    2. 
      
  2. 
        02
        
    Arena
    
        
    Promoted into a SoCBSD arena so other owners of the same board can pile on.
    
      
    3. 
      
  3. 
        03
        
    Review
    
        
    Bots plus humans on Phabricator and GitHub — clean provenance, real names, boot logs.
    
      
    4. 
      
  4. 
        04
        
    Upstream
    
        
    Lands in freebsd-src / the ports tree, and the wiki board page gets updated.

04 — How SoCBSD works

      
Fast to merge, impossible to fake

      

        Work happens in seasonal games: boards are the arenas, contributors are the players.
        The rules exist so that everything merged can survive the trip upstream.
      

    


    
    
      
  1. 
        01
        
    Bring-up only
    
        
    Scope is SoC board support. Not a distro, not a desktop, not a rewrite of FreeBSD.
    
      
    2. 
      
  2. 
        02
        
    Own the hardware
    
        
    You must physically have the device. Support is written against boards, not datasheets.
    
      
    3. 
      
  3. 
        03
        
    Verify, then claim
    
        
    Untested code gets you banned. A boot log is worth more than a paragraph of intent.
    
      
    4. 
      
  4. 
        04
        
    Clean provenance
    
        
    No copying GPL code. Everything must be relicensable and safe to send upstream.
    
      
    5. 
      
  5. 
        05
        
    Real names
    
        
    Upstream FreeBSD wants attributable authorship, so the fork asks for it from day one.
    
      
    6. 
      
  6. 
        06
        
    Review is expected
    
        
    Automated and AI-assisted review runs on every change, then a human signs it off.

05 — Collaborate

        
Got a board? Let's boot it.

        

          I'm open to collaboration on driver work, board bring-up, ports maintenance and
          anything low-level around FreeBSD on embedded hardware. Contract work and
          long-term maintenance included.
        


        
    
          
  • 1
    Pick an arena
    Take an open board, or propose a new one you own.
    • 
          
  • 2
    Build and boot it
    Clone the tree, cut a branch, get to a console.
    • 
          
  • 3
    Send the PR
    Boot log attached. Review is fast; merges are faster.
    • 
          
  • 4
    Upstream it
    Once it's stable, it goes where everyone benefits.
    • 
        


        

          
            Open an issue
            
          
          Reach me on GitHub
        

      


      

        

          

            
            get started
            
          


$ git clone https://github.com/SoCBSD/socbsd-src.git
$ cd socbsd-src
$ git checkout -b arena/my-board gamemaster
$ make -j$(sysctl -n hw.ncpu) buildworld buildkernel \
      TARGET=arm64 TARGET_ARCH=aarch64
→ boot it, capture the log, open a PR
